# proteng-bff

API gateway of ProtEngPlus (Go, Gin). The frontend calls only this service; it checks the JWT and role, then forwards to proteng-user-mgmt (`/proteng-user-mgmt/*`) or proteng-conductor (`/proteng-conductor/*`). It has no database and no RabbitMQ connection. Its Swagger is the API documentation of the whole system.

**This repo is public.** Never add IPs, hostnames of the deploy machines, NodePorts, runbooks or any credential, including in comments and commit messages. Those live in the private repos manual-guides-2023 and devops-infra.

## Commands

- `make check` before finishing any change: gofmt check, `go vet`, `go test`. CI runs the same target.
- `make fmt`, `make run` (regenerates Swagger, then `ENV=local go run main.go`), `make swagger`, `make build`.
- On Windows a CRLF working tree makes `gofmt -l` list every file; that is a checkout problem, not a code problem. Do not "fix" it by reformatting.

## Code layout

- `apis/router.go`: every route and its middleware. `apis/*_handler.go`: handlers and their swag annotations. `apis/forwarder.go`: `Forward`, `ForwardAddParam`, `ForwardAddBody`, `ForwardStrict`, `ForwardWithRawDataResponse`.
- `middleware/authentication.go`: `Authenticate()` and `Authorize(roles...)`. `utils/token.go`: `ValidateToken` with the RSA public key.
- `docs/` is generated by swag. Never edit it by hand and never put other files there. After changing annotations run `make swagger` and commit `docs/` with the handler change.

## Rules

- Every new route gets `middleware.Authenticate()` and the right `Authorize(...)` unless it must work without login (sign up, login, password reset, email verification). `POST /proteng-user-mgmt/admins` is currently open and is a known security issue; do not copy that pattern.
- `ACCESS_TOKEN_PUBLIC_KEY` must pair with user-mgmt's `ACCESS_TOKEN_PRIVATE_KEY` of the same environment. Base64 values must not contain CR.
- New Go functions need a test in a `_test.go` file of the same package, in the same commit.
- A push to `dev` deploys dev and a push to `main` deploys production, even for docs-only changes.

## Team workflow

Issue first with a commit plan, branch from `dev`, Conventional Commits in English with one topic per commit, PR into `dev` using the template in Thai, no emoji anywhere. Full rules: `CONTRIBUTING.md` of manual-guides-2023.
